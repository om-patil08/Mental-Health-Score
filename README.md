Built with scikit-learn, FastAPI, and a vanilla HTML/CSS/JS frontend.

## Overview

This is an end-to-end regression project:

1. **Notebook** – explores the data, cleans it, engineers features, and trains/compares models.
2. **API** – a FastAPI service loads the saved scikit-learn pipeline and exposes a `/predict` endpoint.
3. **Web app** – a responsive single-page UI where a user fills in a form and sees their predicted score on an animated gauge.

The full preprocessing + model is saved as **one pipeline**, so the API just passes raw input to `.predict()` with no manual encoding or scaling.

## Features

- Predicts a continuous **Mental Health Score** from 12 input features
- Compares **Linear Regression** vs **Random Forest**, with hyperparameter tuning (`RandomizedSearchCV`)
- Single saved `Pipeline` (preprocessing + model) – no train/serve skew
- Input validation on both the **client (JS)** and **server (Pydantic)**
- Animated semicircle gauge, loading, error, and result states
- Server-side validation errors mapped back to individual form fields
- Country grouping: top countries kept, all others bucketed as `"Other"`
- Responsive layout and `prefers-reduced-motion` support

## Dataset

**File:** `Student_Social_Media_And_Mental_Health_Impact.csv`

- **5,000 students**, 13 columns
- **Target:** `Mental_Health_Score` (continuous, roughly 3–10)
- **Features:**
  - *Demographics:* `Age`, `Gender`, `Country`, `Academic_Level`
  - *Digital habits:* `Most_Used_Platform`, `Purpose_Of_Use`, `Avg_Daily_Usage_Hours`, `Daily_Unlocks`
  - *Lifestyle:* `Study_Hours`, `Sleep_Hours_Per_Night`, `Physical_Activity_Hours`
  - *Stress:* `Stress_Level` (Low / Medium / High / Very High)

The dataset is not included in this repo. Place the CSV next to the notebook before running it.

## Machine Learning Pipeline

### Cleaning
- Checked for nulls and duplicates (none found; duplicates dropped defensively)
- `Physical_Activity_Hours` contained impossible negative values (min −0.4) → **clipped to 0** rather than dropping rows

### Feature engineering
- `Country` had 111 unique values. The **top 10** most frequent countries are kept and the rest are grouped as `"Other"` → `Grouped_country` (avoids high-cardinality one-hot encoding while keeping the signal)

### Preprocessing (`ColumnTransformer`)

| Columns                                                                 | Treatment                    |
| ----------------------------------------------------------------------- | ---------------------------- |
| `Study_Hours` (skewed)                                                  | `log1p` → `StandardScaler`   |
| `Age`, `Avg_Daily_Usage_Hours`, `Daily_Unlocks`, `Physical_Activity_Hours`, `Sleep_Hours_Per_Night` | `StandardScaler` |
| `Stress_Level`                                                          | `OrdinalEncoder` (Low < Medium < High < Very High) |
| `Gender`, `Academic_Level`, `Most_Used_Platform`, `Purpose_Of_Use`, `Grouped_country` | `OneHotEncoder(handle_unknown="ignore")` |

### Models
1. Linear Regression (baseline)
2. Random Forest (default settings)
3. Random Forest tuned with `RandomizedSearchCV` (15 iterations, 5-fold CV, scoring = R²)

Best parameters found: `n_estimators=200`, `max_depth=15`, `min_samples_split=5`, `min_samples_leaf=2`.

## Model Results

Evaluated on the held-out test set:

| Model                    | Test R² | Train R² | MAE    | RMSE   |
| ------------------------ | ------- | -------- | ------ | ------ |
| Linear Regression        | 0.740   | 0.724    | 0.536  | 0.676  |
| Random Forest (default)  | 0.878   | 0.981    | 0.347  | 0.464  |
| Random Forest (tuned)    | 0.865   | 0.955    | 0.369  | 0.487  |

Random Forest clearly outperforms the linear baseline, capturing non-linear relationships. The tuned model overfits less (smaller train/test gap), while the default model scores slightly higher on this particular test split.

## Getting Started

### Prerequisites
- Python 3.9+

### 1. Clone the repo

```bash
git clone https://github.com/<your-username>/<your-repo>.git
cd <your-repo>
```

### 2. Install dependencies

```bash
pip install fastapi uvicorn pandas scikit-learn joblib numpy
```

Or create a `requirements.txt`:

```
fastapi
uvicorn
pandas
numpy
scikit-learn
joblib
matplotlib
seaborn
jupyter
```

> Use the same scikit-learn version for training and serving, otherwise loading the `.pkl` may fail or warn.

### 3. (Optional) Retrain the model

Open `ML_Project.ipynb`, run all cells, and the last step writes `Mental_Health_Model.pkl`. Put the file in the same folder as `main.py`.

### 4. Run the API + web app

```bash
uvicorn main:app --reload --port 2200
```

- App: http://localhost:2200
- Interactive API docs (Swagger): http://localhost:2200/docs

### 5. Point the frontend at your API

In `static/script.js`, `API_BASE` is currently set to a hosted deployment:

```js
const API_BASE = "https://mental-health-score-h9uh.onrender.com";
```

For local development, change it to:

```js
const API_BASE = "http://localhost:2200";
```

## API Reference

### `POST /predict`

**Request body**

```json
{
  "age": 21,
  "gender": "Female",
  "country": "India",
  "academic_level": "Undergraduate",
  "most_used_platform": "Instagram",
  "purpose_of_use": "Entertainment",
  "avg_daily_usage_hours": 5.5,
  "daily_unlocks": 80,
  "study_hours": 4.0,
  "physical_activity_hours": 1.0,
  "sleep_hours_per_night": 6.5,
  "stress_level": "High"
}
```

**Response**

```json
{
  "predicted_mental_health_score": 6.42
}
```

**Field constraints**

| Field                     | Type    | Allowed values                                                                                              |
| ------------------------- | ------- | ----------------------------------------------------------------------------------------------------------- |
| `age`                     | int     | 10–100                                                                                                      |
| `gender`                  | string  | `Male`, `Female`                                                                                            |
| `country`                 | string  | Any (case-insensitive); unlisted countries are mapped to `Other`                                            |
| `academic_level`          | string  | `High School`, `Undergraduate`, `Graduate`                                                                  |
| `most_used_platform`      | string  | `Facebook`, `Instagram`, `Snapchat`, `Twitter`, `YouTube`, `TikTok`, `LinkedIn`, `LINE`, `KakaoTalk`, `VKontakte`, `WhatsApp`, `WeChat` |
| `purpose_of_use`          | string  | `Networking`, `Education`, `Entertainment`, `News`                                                          |
| `avg_daily_usage_hours`   | float   | 0–24                                                                                                        |
| `daily_unlocks`           | int     | ≥ 0                                                                                                         |
| `study_hours`             | float   | 0–24                                                                                                        |
| `physical_activity_hours` | float   | 0–24                                                                                                        |
| `sleep_hours_per_night`   | float   | 0–24                                                                                                        |
| `stress_level`            | string  | `Low`, `Medium`, `High`, `Very High`                                                                        |

Invalid input returns a standard FastAPI `422` response, which the frontend maps to the matching form field.

**Example with cURL**

```bash
curl -X POST http://localhost:2200/predict \
  -H "Content-Type: application/json" \
  -d '{"age":21,"gender":"Female","country":"India","academic_level":"Undergraduate","most_used_platform":"Instagram","purpose_of_use":"Entertainment","avg_daily_usage_hours":5.5,"daily_unlocks":80,"study_hours":4,"physical_activity_hours":1,"sleep_hours_per_night":6.5,"stress_level":"High"}'
```

## Frontend

The UI is split into a form panel and a result panel:

- **Form:** three sections (Profile, Academic & Digital Habits, Lifestyle & Stress) with inline validation
- **Result panel:** four states – idle, loading, result, and error
- **Score bands:**

  | Score  | Signal   |
  | ------ | -------- |
  | < 4    | Strained |
  | 4 – 7  | Balanced |
  | ≥ 7    | Strong   |

## Deployment

The backend is deployed on [Render](https://render.com) (`API_BASE` in `script.js`). To deploy your own:

1. Push the repo (including `Mental_Health_Model.pkl` and the `static/` folder) to GitHub
2. Create a new **Web Service** on Render connected to the repo
3. Build command: `pip install -r requirements.txt`
4. Start command: `uvicorn main:app --host 0.0.0.0 --port $PORT`
5. Update `API_BASE` in `static/script.js` if you host the frontend separately

> On free hosting tiers the first request after inactivity can be slow while the server wakes up.

## Limitations

- The score is a statistical estimate learned from one dataset, **not** a diagnosis
- The model captures correlation, not causation
- Performance depends on the dataset's distribution and may not generalize to other populations
- Country grouping means less common countries are all treated as `"Other"`
